# Standalone configuration — v0.6.0-beta

The data root is `%LOCALAPPDATA%/ConduitClient/` in Minecraft's Windows/Proton profile. `config.json` is created automatically with the diagnostics defaults below. There are no user-facing reload settings. Initialization and targeted JSON UI reload are automatic.

On startup, the obsolete keys `enabled`, `resourcePackPath` and `reloadMode` are ignored regardless of their former values/types and removed through temporary-file replacement. Unknown keys are preserved. The old settings cannot select a broad reload path. Non-object, invalid or oversized (>16 KiB) files fail startup without changing the original. Write/replacement failures fail safely. `DISABLE` remains an operational stop sentinel outside configuration.


## Diagnostics

```json
{
  "ui_scale": 1.0,
  "diagnostics": {
    "factories": {
      "enabled": true,
      "empty": true
    }
  }
}
```

Settings are read on startup; restart Minecraft and inject again after editing.
`ui_scale` controls the font size, spacing, and padding of both the F3 diagnostics and the F5 tooltip. It accepts values from 0.25 to 4.0, with 1.0 using Minecraft's native UI scale. On startup, Conduit moves an existing `diagnostics.scale` value to `ui_scale`. If both keys are present, `ui_scale` takes precedence.

`factories.enabled` shows or hides the entire factory section. `factories.empty: false` hides factory rows only when both live roots and controls are zero. These switches affect presentation, not sampling or diagnostic logging. Viewport clipping can still omit rows to keep the panel on screen.

Missing fields receive defaults; unknown fields are preserved. Invalid types or out-of-range scales fail startup with a logged error and leave the original config unchanged.

## Native reload admission

Ctrl+R dispatches Minecraft's targeted JSON UI reload for its mounted definitions directly. ConduitClient does not scan or validate resource-pack JSON before dispatch, so unrelated files such as `texts/languages.json`, inactive packs and disk parse errors cannot block the shortcut. Minecraft owns definition parsing and error handling; ConduitClient does not promise rollback on native parsing errors. Continuous disk watching remains disabled. No manual resource-pack path is needed.

Executable compatibility, native context/thread-affinity checks, serialization and shutdown guards still apply. The internal discovery and JSON parsing utilities remain available for foundation/development callers.

## Logging

The layout is:

```text
ConduitClient/
  config.json
  logs/
    standalone.log
    native-stages.log
    client.log
```

The logger creates missing parent directories and appends. Previous root-level logs remain untouched; new automatic logs use `logs/`. Foundation automatic logging also uses `logs/conduit.log`; explicit foundation C API clients continue to own their supplied log paths. No automatic rotation/deletion occurs. If a directory cannot be created or a log cannot be opened, initialization fails with debugger output rather than falling back to a root-level file.

## Experimental title-logo cache

The title-logo renderer writes the embedded PNG into `ConduitClient/cache/` for Minecraft’s native RawPath texture loader. This file is generated by the DLL; users do not supply it or install a pack. Unknown/customized global-pack profiles retain the original logo. See [the fix notes](title-logo-fix.md).
