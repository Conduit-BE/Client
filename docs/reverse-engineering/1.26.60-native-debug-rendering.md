# Native F3 rendering — Bedrock 1.26.60.5

Tested 2026-11-07, Windows GDK x64, package 1.26.6005.0, through
BedrockOnLinux/GDK-Proton. Version identification and complete executable SHA256
verification reuse the standalone reload backend. Original executable SHA256:
`1d6ad5c217e9305442c353ba3e9bca623d5719134e1cc8a84fb1233f7145e85c`.
All RVAs below belong exclusively to that image. They are not portable signatures.

## Question and method

Can diagnostics use Minecraft's font and UI renderer without a resource pack or
another screen/window? The former implementation was a layered Win32 popup,
using GDI Consolas, screen-space coordinates, monitor work-area intersection and
right alignment. Its placement depended on the desktop compositor rather than
the game's viewport. That entire rendering path has been removed.

Reused the saved `UIScene::render` / `ScreenView::render` investigation and exact
build Ghidra project. Bounded disassembly/decompilation used PE exception-table
function boundaries and `tools/reverse-engineering/ConduitUiProbe.java`.
Temporary 20-second Frida observations inspected only these natural calls.
An additional bounded drawing experiment called the verified methods from the
end of a natural ScreenView render, restoring clipping and color afterward.
No font assets or game/resource-pack files were copied or changed.

## Confirmed observations

| RVA / member | Evidence and role |
| --- | --- |
| `0x4ccf520` | UIScene render constructs a UI render context on its stack, renders its ScreenView, finishes the context and destroys it. |
| `0x6c0a1d0` | Context constructor: `(context, scene UI service, ScreenContext, scene)`; assigns vtable `0xf2d18c0`. Reserves 64 text records. |
| `0x4cb3260` | ScreenView render: `(view, context)`; supported context remains alive when this function returns to UIScene render. |
| context `+0x10` | Borrowed ScreenContext; `+0x120` is the scene. Production drawing does not traverse that scene or its UI tree. |
| context `+0x80/+0x88/+0x90` | Deferred-text begin/end/capacity; 104-byte records, first qword a borrowed font. Natural flush consumes records and resets end. |
| `0x6c0b230` | Text flush: `(context, float deltaTime in XMM1, uint64 packedDepthAndFlag in R8)`. Low 32 bits are floating-point depth bits (MOVD), not an integer depth; bit 32 suppresses font animation timer advancement. Natural calls observed from return RVA `0x4cb7c16`, e.g. R8 `0x13c23d70a`. |
| font vtable `0xf0ea8a0` | Natural vanilla text, including “Save & Quit”, uses this implementation. Custom BeHub text also used another font implementation (`0xf21fc50`), which is deliberately not selected. |
| `0xe6be40` | Vanilla font vtable slot `+0x30`: `unsigned width(font, {const char*, size_t}*, float scale, bool)`. Returns rounded width through RAX, not float XMM0. Static wrapper `0x6c0a920` adapts a read-only MSVC string to this span. |
| `0x6c0ac90` | Borrowed text submission: `(context, font, Rect*, Span*, RGB*, float alpha, uint32 alignment, Measure*, Caret*)`. Native records borrow the span until flush. |
| text arguments | Rect order left/right/top/bottom. Span is two qwords. Measure has float scale, float spacing, two flag bytes; observed vanilla scale 1, spacing 0, flags 0. Caret is int32 -1, alignment 0. These were verified against natural text and static field copies. |
| `0x6c11440` | Filled rectangle `(context, Rect*, RGB*, float alpha in XMM3)`. Calls `0x24e5500`, which submits four corner vertices through the existing UI tessellator/material. Not an outline or a swap-chain hook. |
| ScreenContext `+0xa0` | Live GuiData. Logical viewport width/height `+0x50/+0x54`; scale `+0x5c`, inverse `+0x60`. Observed 1894×1019 physical, 631×340 logical, scale 3. The renderer reads logical dimensions every drawing callback. |
| `0x6c11670` | Native clipping helper `(context, Rect*)` converts GUI coordinates to GPU pixel scissor. GuiData scale accessor `0xe7e290` normally returns `+0x5c`, with an alternate native scale path. |
| ScreenContext render state | `+0x30` points to RGB/alpha plus dirty byte (17 bytes); `+0x10` points to graphics context, whose `+0x94` contains four int32 scissor fields. Static native rectangle/clipping writes verify these layouts. Drawing saves/restores both, including the color dirty flag. |

The bounded draw test returned normally with width 177 for its 36-byte caption,
a 631×340 logical viewport and the observed vanilla font table. A subsequent
standalone DLL visual capture showed the panel above BeHub `small_chest_screen`,
anchored at logical (8,8), in the actual native font. Existing observations still
reported 770 elements / 3 instances / 7 roots / 280 generated controls. Ctrl+R
completed on the verified UI thread with the native renderer enabled. These are
limited observations, not comprehensive in-game acceptance testing.

## Implementation and ownership

`src/platform/windows/native_debug_renderer.cpp` hooks only ScreenView render and
native text flush, after the existing backend's complete image verification.
The callbacks run in the existing native UI render call chain (observed thread
280). A scoped thread-local frame records an already-used vanilla font from at
most 64 naturally queued text records and copies the natural flush flags.
It retains no context/font pointer after ScreenView render returns.

After original ScreenView render, drawing requires an empty native text queue
and enough existing capacity for every overlay row. Otherwise it skips drawing.
It uses the native full-viewport clipping helper, fills a near-opaque dark
rectangle, submits native text, then synchronously flushes its borrowed spans.
The font animation timer is not advanced a second time. Original clipping and
color state are restored. Contexts and native text storage are never constructed
or destroyed by ConduitClient.

No screen is pushed, no control is added, no hierarchy is traversed, and no
DXGI buffer, command queue or device state is managed by this renderer. Existing
DXGI hooks still measure FPS only. Their temporary public D3D11 probe now uses
the existing game HWND; it creates no desktop window.

The worker still formats copied diagnostics at 4 Hz and handles F3 rising edges.
A fixed-buffer mailbox uses try-lock reads; locks are released before native
calls. Fixed-buffer layout is cached until text, viewport dimensions or font
identity change. Native width measurements may allocate internally; they occur
on layout changes, not for every row every rendered frame. Conduit text
submission uses already reserved native capacity. No zero-overhead claim is made.

Each eligible legacy ScreenView draws after its ordinary content. Multiple
eligible layers can redraw the same panel; the later legacy layer covers earlier
ones, without changing the screen stack. Native toast/HBUI composition may still
appear above it. Resize/device recreation require no retained GPU resources:
new contexts and viewport dimensions are used on the next callback.

## Limitations and validation

High confidence for the exact-build ABI and the observed chest rendering path.
A frame must naturally use the supported vanilla font and text-flush path. Pure
HBUI screens, text-free/hidden HUDs, other context/font implementations, a busy
mailbox, or a nonempty/full native text queue can suppress the panel rather than
reuse a stale native pointer. Complete visibility on HBUI/title screens is not
established. There is no speculative graphics or OS-window fallback.

Layout uses native logical pixels, a scale-0.7 native font, 8-pixel margin,
4-pixel padding and 8-pixel rows. Widths are measured with that font. Narrow
rows receive UTF-8-safe ellipses; crowded factory lists receive an omission notice
while preserving footer statistics where space permits. All details remain in
`standalone.log`. Extremely small logical viewports suppress rendering.

Automated portable layout/mailbox tests and Windows input/FPS/statistics smoke
tests do not validate Minecraft's ABI or pixels. User acceptance must still
check HUD, pause, inventory, BeHub; F3 open/close; window resizing; fullscreen;
GUI scale; Ctrl+R; and stability/performance. No release or push is authorized.

### Compact layout revision

The panel now uses native `§b§lConduit Client§r` title formatting and indented
`current screen`, `renderer`, and `reloads` sections. A factory's `children` value
means retained generated roots; its `elements` includes those roots and their
unique descendants, preserving the existing census semantics. The font scale is
0.7, measured and drawn consistently, and background alpha is 1.0. Factory rows
are omitted in complete three-line groups when space is constrained, with a
notice and preserved footer. At most 60 rows fit within the existing 64-record
native text capacity. No new native entry points or diagnostic collection changes.

The final compact presentation contains `current screen` (type, elements,
per-factory children/elements) and `general` (DXGI FPS, Conduit build version,
client version). Reload statistics and factory totals remain collected/logged but
are omitted from the panel. Conduit version comes from CMake project metadata
(`v0.3.0-beta`); the client label identifies the exact image already verified by
the standalone backend (`1.26.60.5`), not an unchecked executable guess.
