## Evidence and native sequence

The earlier failed loader-only path read the edited bytes but retained the old visible UI. The successful outer resource reload contains unrelated material stages: helper `0x8c1e80` loads `materials/common.json`, `materials/sad.json` and `materials/fancy.json`. It is deliberately excluded from the new mode. Other investigated outer helpers remain excluded; none was assumed to be a UI invalidator from proximity.

The registered `button.reload_ui_definitions` callable points to callback **RVA `0xf203e0`**, which constructs a guarded context wrapper from incoming R8, manages its reference counts, and invokes action **`0x6583170`**. Assembly establishes that incoming RCX/RDX are unused before being overwritten; no incoming stack argument is consumed. The prototype calls this native callback with unused null RCX/RDX and the validated context in R8. It does not construct a fake C++ wrapper or mutate Minecraft object fields itself.

The existing action performs this ordered sequence:

1. Context virtual slot **`+0x270`** obtains the reload owner. Owner slot **`+0x60`** calls legacy definition loader **`0x83a190`**, retaining its existing asynchronous globals and apply/completion path.
2. Owner slot **`+0x68`**, target **`0x8ac660`**, returns a guarded wrapper whose object is the current service at owner **`+0x818`**. The wrapper's first pointer is a lifetime guard, not another service object. Its object calls service slot **`+0x28`**, resolved to **`0xde790`** from the already-observed service table **`0xefca210`**.
3. Native **`0xde790`** calls **`0x1872e40`** for category keys **15, 16 and 4**, the last as a tail jump. Bounded decompilation establishes lookup/wait/pump operations on category task groups, with internal synchronization. **This is not established as a cache-clear method**, and enum names are not recovered.
4. Context slot **`+0x790`** obtains a collection owner. The native action destroys its tree nodes through **`0x58f570`**, restores sentinel links, and clears its size. This supplies an explicit collection invalidation absent from loader-only dispatch. Describing that collection as a UI factory/definition cache is an interpretation supported by its use in this registered UI reload action; no recovered C++ class name is claimed.

The callback, wait and tree operations are retained as one existing native action. No speculative combination of independently invoked preparation helpers is used. It does not call V5 outer entry `0x873a20`, material stages, or resource submitter `0x8c4f40` directly. Actual resource isolation still requires the user test: the wait routine can pump pre-existing queued work, and the complete transitive runtime behavior has not been exhaustively traced.

## Concrete context and ownership

One bounded passive frame observation, followed by one read-only node query without additional hooks, resolved the context source in the running game:

- Verified frame **`0x879030`**, caller **`0x83274`**, thread **280** in this launch; owner table **`0xf091b70`**, service table **`0xefca210`**. No thread/heap address is compiled in.
- The legacy owner collection at **`+0x9d0`** is already traversed by the native loader/completion. Completion instructions `0x8f612c–0x8f613d` pass the node's **`+0x38`** object to virtual slot **`+0x730`**. This supplies an actual live context instead of assigning a type to an unrelated owner member.
- The selected context table is **`0xf2b9330`**. Slot **`+0x270`** resolves to **`0x1a58900`**, exactly `RAX = [RCX+0x1c8]; ret`. Slot **`+0x790`** resolves to **`0x56f040`**, exactly `RAX = [RCX+0x230]; ret`. Slot **`+0x730`** resolves to **`0x65b4090`**.
- The prototype requires one client in that current collection, exact table/getter entries, context **`+0x1c8`** equal to the live incoming frame owner, live context/service guards, and a readable sentinel-shaped collection at context **`+0x230`**. It fails closed for multiple clients, mismatched ownership or missing objects.
- Owner **`+0x6a0`** is a different object; its short table does not supply these context getters. It is not used. An early read-only probe misinterpreted a service lifetime guard and caught a pointer-read exception; it detached with `crash:null`, made no native call and left Minecraft alive. Corrected interpretation came from the complete `0x8ac660` assembly, not repeated speculative calls.

The guarded context is reacquired from the current natural frame, validated before dispatch and used synchronously on that frame's verified thread. The original callback handles guard-reference acquisition and release. No callback/heap pointer is retained for later targeted invocation.

## Implementation boundaries

`reloadMode` is an optional persistent setting:

- **`FullResourceReload`** (default): unchanged V5 call and arguments at `0x873a20`.
- **`LegacyJsonUiOnly`**: experimental native callback at `0xf203e0`, protected by its original code prefix and the additional context checks above.

Standalone initialization, exact-image and existing owner/service/context checks are retained. Requests are serialized, JSON is validated only on Ctrl+R, and continuous file watching remains disabled. A completion barrier requires both the matching loader completion and the native action's return; neither event alone releases the request. It covers callbacks delivered while the native action pumps task groups. Guard failure or timeout latches a fault; targeted mode never silently falls back to the broad reload.

The native category-wait routine has no demonstrated cancellable deadline. Conduit's worker still faults after eight seconds, but cannot safely interrupt an already executing native action. DISABLE prevents further requests and retires Conduit's hooks; it cannot cancel native work already running. Restart rather than repeatedly retrying if Minecraft becomes unstable. JSON syntax validation does not guarantee Minecraft semantic validation or transactional rollback.

## One controlled visual experiment

Build in a fresh directory with `CONDUIT_STANDALONE_LEGACY_RELOAD=ON` as in [the standalone guide](../standalone-initialization.md), using `.local/build/legacy-ui-only`. Inject only `.local/build/legacy-ui-only/standalone/ConduitClient.dll` into a fresh Minecraft process. Set `"reloadMode": "LegacyJsonUiOnly"` in the existing config alongside the active pack path. No Frida/controller or manual `/reload all` is needed.

Hypothesis: the complete native UI button action, including its category barrier and final collection invalidation, applies edited definitions without the broad resource operation. Confirmation requires a visible edit after reopening its screen **and** no chunk/texture/skin refresh, followed by repeated successful edits without progressive freezes. A native completion/log alone does not confirm it. Guard rejection, no visible edit, unrelated resource changes, instability or growing latency rejects or limits the hypothesis.

Use an already visible BeHub label/element and make a reversible manual edit; Conduit has not modified the pack. Press Ctrl+R once, reopen the screen and report appearance, chunks, textures, skins and freeze. Stop for user feedback before another build. Create the existing DISABLE file to prevent further dispatch; to return to V5, choose `FullResourceReload` and restart Minecraft with the preserved Beta 1 DLL.

## First in-game confirmation — 2026-11-06

The user confirmed: the edit appears, the freeze is noticeably smaller, and chunks/textures/other resources did not visibly refresh—only UI. This establishes visual functionality and observed resource isolation for that test, separately from native completion counts. It does not establish exhaustive transitive resource isolation or long-run stability.

The user’s smaller-freeze observation remains qualitative. Local evidence: `first-visual-confirmation.json`, plus the current standalone stage log.
