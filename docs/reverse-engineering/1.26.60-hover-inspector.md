# Legacy UI hover inspection

On 2026-11-13, the local Windows GDK x64 executables reported file versions
`1.26.60.5`, `1.26.62.1`, and `1.26.63.1`. Compare the functions below using PE
unwind bounds and Capstone, masking relative branch and RIP-relative operands.
The matched function bodies preserve the field accesses across these builds.

In 1.26.60.5, `0x1c68360` computes cached absolute position at control `+0x10`
and clears dirty bit 0 in `+0x18`. The native containment check in
`0x1c52140` adds the size at `+0x48` to that position. The traversal at
`0x4c6dd90` adds the control's layer at `+0x68` to the inherited layer,
propagates visibility from bits `0x0c` at `+0x18`, and visits children in
vector order. The corresponding traversal addresses are `0x4c6df60` on
1.26.62.1 and `0x4c6dcc0` on 1.26.63.1.

Conduit reads the active legacy view on its render thread and uses this layer
and tree order to choose a visible control. Its highlight represents the
control's layout bounds.

## Resolved JSON type

On 2026-11-15, static inspection used the installed 1.26.60.5 Windows GDK
x64 PE from the [UI controls investigation](1.26.60-ui-controls.md).
Disassemble with `objdump -d -Mintel` and use the PE unwind table to
bound the functions. Follow the control factory at `0x1c6ccc0` to the
type getter call at `0x1c6d3e3`. Its target `0xf3600` looks up
`type` through the resolved-property accessor `0xf0fa0`. The getter
passes a pointer to a native string view containing a data pointer and
length. The resulting string value has tag 4 at `+8`. The string conversion
at `0xe931540` follows two pointers from the value to the NUL-terminated
data. The direct callers at `0x1c6c358` and `0x1c7ee66` pass the
resolved definition in R9 and an output shared control in RDX. The factory
writes the object and owner to this output and returns it.

The F5 inspector copies the resolved type while the factory caller still
owns the definition, then associates it with the returned control and
its shared owner. The destructor at `0x1c65f60` removes the association.
The inspector checks the control's weak self owner before returning the
label. There is no list of names to maintain. Controls created before
capture begins or through an unobserved construction path show
`unknown`. Reopen the screen or use Ctrl+R after late injection to
rebuild controls through the factory.

The DLL searches near the profile's sprite renderer for unique factory and
destructor signatures, verifies their unwind entries, and checks both
relative calls and the `type` key before enabling capture. The signature
chain was checked against the installed 1.26.60.5 PE. Capture on other
profiles depends on those checks passing in their running images.

To verify in game, start with a legacy screen containing separate hit
regions for several control types. Include types such as `grid`, `toggle`,
and `stack_panel`, and compare F5 labels with the effective JSON definitions.
For composite controls, hover an exposed part of the parent to inspect
the parent. Repeat after Ctrl+R and reopening the screen.

### Live verification

Injected the rebuilt standalone DLL into Windows GDK 1.26.60.5 under
BedrockOnLinux and Proton on 2026-11-15. The native log recorded
`native_hover_types_installed` and a completed Ctrl+R cycle on the game
thread. F5 observations after reconstruction included `title_image`
as `image`, `paper_doll` as `custom`,
`common_buttons.new_ui_binding_button_label` as `label`, and
`paper_doll_panel` as `panel`. The Pause screen tooltip visibly
reported `pause_screen_main_panels` as `stack_panel`. A hover on
a title control created before injection initially showed `unknown`
and showed its captured type after reconstruction.
