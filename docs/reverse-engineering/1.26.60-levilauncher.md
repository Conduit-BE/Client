# LeviLauncher 1.1.0 executable identity

On 2026-11-12, two LeviLauncher 1.1.0 instances installed the Windows GDK x64
release 1.26.60.05 from package 1.26.6005.0. Both instances contained the same
patched executable, SHA-256
`019f4ee7c82db0e0c187653bc76c61cf75502ff6866a5cc6603fa0c909a386a2`.
Their `.orig` backups had SHA-256
`988f6a61403b4381aa41e6c66d64cce441b14e561a9b10f647c2758ef3f2672a`.

Read the PE section table of each local image and compare each section's RVA
and raw bytes. All eight original sections match between the patched image
and its backup, including code, read-only data and unwind metadata. The patched
image adds `.levildr`. Resolve the eleven instruction prefixes declared in
`src/minecraft/versions/bedrock_1_26_60_5.hpp` through the PE section table.
All eleven match at the recorded RVAs in both images.

In the patched image, ten vtable entries for the loader, owner wait and
frontend stack, client owner, cache and player stack, service method and wait,
and legacy scene render and view thunk resolve to the previously documented
targets. The getters at `0x1a58900` and `0x56f040` still return the fields at
`+0x1c8` and `+0x230` respectively.

This establishes that the LeviLauncher patch preserved the original sections
and that the existing entry guards match. The BedrockOnLinux reference image
was unavailable for a full section comparison. Runtime checks are required
for structure layouts and native behavior. The compatibility selector accepts
the exact patched hash, preserves the existing reference hash, and retains the
runtime guards.
