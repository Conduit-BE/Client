## Implemented semantics and lifetime

- **Factory instances**: exact verified factory components attached to unique controls in the selected active legacy screen, including invisible owners. Multiple components/names are instances, not unique definitions.
- **Generated controls**: union of active-screen controls reachable through owned child edges from those factories' currently live generated roots, including roots and invisible descendants. Shared or nested subtrees are counted once. This describes subtree membership, not independent provenance for every descendant or the number of native creation calls.
- **Roots**: unique retained generated roots with a nonexpired weak owner and membership in the same active hierarchy. Expired references and other screens are excluded. Zero is distinct from unavailable.
- No global-definition count, cumulative generation counter, per-factory standalone breakdown or binding-value inspector is implemented. Native names/per-factory associations above were confirmed in bounded investigation only.

`src/core/factory_census.hpp` holds a fixed graph and unique-root/subtree algorithm. The existing element traversal records callback-local edges/handles; a separate soft **5 ms** pass reads factory components and their weak lists after a complete element traversal. Existing element traversal retains its own soft 5 ms budget; factory failure cannot overwrite a valid element count. Together, work can approach 10 ms on a sample; OS read latency/clearing scratch can overrun soft deadlines. No worst-case FPS claim is made.

Sampling remains at most once/second for an unchanged name and at the existing screen-name change boundary. All borrowed handles are cleared on callback exit. Only copied numeric results enter the coherent expiring screen snapshot. No additional native hook, native call, pointer retained between samples, lock across reads, or traversal from DXGI Present is introduced.

Limits: 8,192 active controls, 32,768 child edges and inspected weak entries, max 8,192 weak entries/component, max 128 packed component pointers/control. Failed reads, changed descriptors, unknown layouts, missing type bit, incomplete element snapshot or factory deadline produce factory `Unavailable` rather than a partial exact total. Existing title/Play/HBUI/split-screen limitations persist.

### Implementation and log contract

The existing aggregate algorithm and selection are retained. `FactoryCensus` additionally counts one selected factory's roots/subtree at a time, using the same bounded graph and deadline, and then computes the original all-factory union. At most 32 detailed rows are copied into the coherent expiring screen snapshot. More instances retain the aggregate total and explicitly mark detail truncation. Unreadable labels are `Unavailable`; known empty names remain empty. Names are bounded to 96 copied bytes with explicit truncation flags. No source-origin classification is hardcoded into the DLL.

Each row has `instances=1`. Same-name components are not merged or mislabeled as unique definitions. Anonymous instances receive `position-<hash>` diagnostic IDs derived from first-parent child ordinals in the active screen hierarchy, never from addresses. IDs remain stable when that structural position is unchanged, including same-shape reconstruction; they are screen-scoped structural fingerprints, not permanent object IDs, and can change when sibling order/topology changes. Copied native owner names accompany them.

The panel stays unchanged. Its existing worker writes changed breakdowns to **`standalone.log`**, at most one block per two seconds while F3 is visible and Minecraft focused. Each block has a snapshot sequence and screen name; each row records the native name/owner availability and truncation, structural ID, instance count, roots, `controls_including_roots`, and `descendants_excluding_roots`. Unchanged counts are logged again after a successful Conduit reload. Unavailable snapshots are labeled; brief transitions may be coalesced. This is a sampled diagnostic, not a complete creation-event trace. Formatting, file writes and logger locks occur on the overlay worker, not the native UI callback or DXGI Present.

Synthetic tests cover per-instance empty factories, shared/cyclic/nested subtrees, duplicate roots, a stable structural position after rebuilding, changed/removal snapshots, unavailable/limited graphs, copied labels/rows and expiry. The Windows overlay smoke additionally checks real diagnostic output for a named and empty-name row. Actual changed item quantities and user verification are still required; unchanged quantities after a reload legitimately keep identical counts.
