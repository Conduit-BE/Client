# Bedrock 1.26.65.1 compatibility profile

On 2026-11-16, the installed Minecraft for Windows GDK package reported
`1.26.6501.0` and `x64` in its app manifest. The PE file version of
`Minecraft.Windows.exe` was `1.26.65.1`.

## Investigation

Compare the reload, diagnostics, and title-logo functions with the
[1.26.63.1 profile](1.26.63-compatibility-profile.md). Use the PE unwind
records for function boundaries. Disassemble the relevant functions with
Capstone, masking RIP-relative displacements and relative branch and call
operands. Match vtables in `.rdata` by their function pointers at the same
slot offsets. Resolve the scene-name getter through the scene stack table
at slot `+0x128`. Follow the RIP-relative references to the component masks
from the constructors at `0x1c8ca00` and `0x1c8b080`.

## Observations

- All compared functions with unwind records matched over their full lengths
  after masking. The UI reload callback remains at `0xf20000`. The view
  render entry is `0x4cb3210`, and the primary screen-name call returns to
  `0x65b1109`.
- The matched vtables moved by `0x1000` with `.rdata` and retained their
  inspected slots. The getter at slot `+0x128` still points to `0x56ca20`.
- The matched component constructors reference the factory mask at
  `0x128f8dc8` and the binding mask at `0x128f8e28`.

All addresses above are module-relative and specific to `1.26.65.1`.

## Client impact and validation

The `bedrock_1_26_65_1.hpp` profile uses the relocated entries and reuses
the previous profile's layouts and instruction guards. The matching
function bodies support reusing the inspected layouts. In the installed
1.26.65.1 game, the standalone DLL initialized, drew the title logo, and
logged a complete title-screen control sample. The native reload hook
armed and hover type tracking installed. Verify the F3 and F5 overlays
visually and test Ctrl+R with a visible edit in an active JSON UI pack.
Use Ctrl+K to check hook retirement after testing.
