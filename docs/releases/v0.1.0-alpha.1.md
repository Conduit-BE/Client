# ConduitClient v0.1.0-alpha.1 — Experimental Native Reload

First alpha for **Minecraft Bedrock Windows 1.26.60.5**, GDK x64, package **1.26.6005.0**, tested through BedrockOnLinux/Proton. Other builds are unsupported and rejected by the native image check.

## Features and limitations

- Ctrl+R invokes the native resource reload at RVA **0x873a20** on the observed game thread.
- Edited legacy JSON UI becomes visible after reopening the affected screen; human-confirmed in-game without manually running `/reload all` for each edit.
- JSONC validation and file monitoring, including referenced custom definitions outside `ui/`.
- Separate opt-in experimental DLL; the foundational DLL remains unchanged in its default unsupported backend behavior.

**This is not JSON UI-only hot reload.** Other client resources and chunk rendering refresh. A roughly one-second freeze can occur, and player skins may become invisible. Automatic native reload on file changes is disabled; press Ctrl+R. Minecraft's semantic UI validation and transactional rollback are not guaranteed. Broader effects remain incompletely characterized.

**Experimental alpha: back up your worlds and use at your own risk.**

## Install and disable

Use [the experimental setup guide](../experimental-legacy-reload.md). This is an advanced developer alpha requiring the Windows Frida 17.23.2 server inside the tested Proton context, matching Node bindings, current process/thread observations and explicit initialization. DLL injection alone does not enable it. One-time setup may require a control `/reload all` to observe the thread; normal edits use Ctrl+R. Set the active resource-pack **root**, not Conduit's unrelated staging directory, and use a writable ignored output directory.

Create `DISABLE` in the running prototype controller's output directory to stop the worker and retire its hooks. Do not force-unload the pinned DLL. Stopping the diagnostics/controller alone does not disable an active native backend.
