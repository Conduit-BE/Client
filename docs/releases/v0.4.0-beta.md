# ConduitClient v0.4.0-beta — QOL update

2026-11-08. Experimental GitHub pre-release for the exact supported Minecraft build. Published at the user’s request after automated build/test. Native in-game regression verification remains pending.

## Implemented

- Standalone initializes automatically; configuration defaults to `{}`. Obsolete activation, manual resource-pack path and JSON UI mode keys are ignored/removed atomically while unknown keys survive. Invalid files fail safely.
- Known Windows profile layouts are searched on each requested reload for disk UI pack preflight checks. Minecraft still owns pack mounting. Discovery limits, unsupported layouts and no-candidate behavior are explicit in [configuration](../configuration.md).
- Automatic diagnostic logs append under `%LOCALAPPDATA%/ConduitClient/logs/`. Missing parents are created; old root logs remain untouched. Foundation automatic logging follows the same layout.
- Removed the broad resource reload implementation, selection branches, exported fallback configuration API and obsolete tests/controller calls. Ctrl+R dispatches only the complete targeted native UI action.
- Introduced executable identity detection, exact SHA/AMD64 selection, dedicated native profiles, typed address/layout/signature access and feature gates. Only the previously verified Bedrock GDK x64 **1.26.60.5**, package **1.26.6005.0**, is supported. File-version metadata is read diagnostically; a matching version string cannot authorize an unknown image.
- Ctrl+K requests deactivation from the standalone initialization worker, once per focused press. Startup-held chords and focus changes do not synthesize presses. F3/native rendering and Present measurement stop, reload admission closes, pending requests wake, the client worker joins, and hooks are disabled. DISABLE remains supported.
- Embedded the 2004×686 logo PNG as DLL RCDATA 104; resource access uses bounded header checks with no repository-relative runtime path.
- Retained targeted reload, native renderer, screen/element/binding sampling, factory breakdown, FPS and reload statistics. The overlay build label now uses the selected compatibility profile.

## Incomplete features and blockers

**Physical DLL ejection is not implemented.** The existing initialization and hook architecture permanently pins the module and retains trampolines/resident callback diagnostics. There is no proof that every thread has returned from DLL/native callback code. Safe deactivation is the supported behavior; no FreeLibrary is called from a hook. An already executing native operation cannot be safely interrupted. Restart Minecraft to reactivate.

**Main-menu logo replacement is not implemented.** The PNG is embedded and its bytes were verified in the DLL, but the exact title image control, definition origin, image setter and texture ownership ABI remain unverified. REA identified the exact executable; Hopper bridge startup timed out before its string query returned. This is not evidence that a path is absent. No global texture override or guessed name-based hook was added; all original logos remain unchanged. See [findings and safe next steps](../reverse-engineering/1.26.60-title-logo.md).

Disk discovery identifies candidates rather than proving the active pack set. Inactive candidates can conservatively block preflight on invalid JSON; encrypted, world-embedded and arbitrary external launcher pack layouts are not enumerated. No-candidate requests are logged and use Minecraft's own mounted-definition action. The native callback does not promise transactional rollback on Minecraft semantic errors.

## Automated verification

Portable CTest: **10/10 passed**. Windows/Wine CTest: **22/22 passed** (107.71 seconds). Coverage includes configuration migration, malformed input preservation, automatic pack discovery, log creation/preservation and filesystem failure, exact build selection/rejection and feature gates, initialization state/keypress policy, worker serialization and shutdown during an active operation, unsupported-host startup, duplicate loading, DLL lifecycle, input/overlay tests, screen/control/binding/factory metrics, FPS and D3D12 pixel/hook tests.

The first sandboxed Wine attempt could not start Wine's local socket. Running with the required local socket/desktop access resolved that environment issue. Two stale test expectations (old version label and old root log path) were corrected before the final run. Build output includes existing FARPROC cast warnings in dynamic-loading tests; no build errors remain.

These tests run synthetic hosts. They do **not** verify Minecraft hook behavior or actual visual reload in this new build.

## Required in-game verification

1. Start a fresh supported Minecraft process with only this standalone DLL; inspect logs and automatic affinity arming. Confirm config migration and logs directory in the actual profile.
2. Save visible edits in the already active UI pack, press Ctrl+R repeatedly, reopen the affected screen and confirm edits. Check chunks, textures, skins and pauses for regression; test invalid JSON preflight too.
3. Toggle/hold F3, switch title/Play/world/inventory/pause/custom screens and check screen detection, elements, bindings, factory totals and per-factory rows, FPS, reload timing/counters and native rendering.
4. Press Ctrl+K while F3 is visible, while idle, and with a queued/active reload. Verify Minecraft remains usable, F3 disappears, and later Ctrl+R/F3/Ctrl+K presses have no Conduit effect. Module residency is expected. Test DISABLE separately.
5. Confirm original logos remain unchanged on the title, customized title, loading screens and in-game interfaces. Title replacement remains blocked rather than assumed complete.

Publication was explicitly authorized. The checks above remain required before claiming in-game verification or broad native stability.
